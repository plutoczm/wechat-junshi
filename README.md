# 微信恋爱军师 · wechat-junshi

把 [goutoujunshi](https://github.com/shengjidaguai-china/goutoujunshi)（狗头军师）这个
"恋爱军师" skill 接到微信上，**只对你指定的好友**自动回复，带本地对话档案作为上下文。

用你自己的 DeepSeek 额度，没有第三方服务费，没有中转服务器——**所有数据都在你本机**。

```
微信好友发消息
   ↓  轮询会话列表（wxauto4 + Windows UI Automation 驱动本机已登录的微信）
   ↓  好友过滤：不在名单里的人、所有群聊，一律不处理
   ↓  归档：把读到的每条消息写进该好友对应的本地档案
   ↓  切换校验：确认当前窗口就是目标好友，否则绝不发送
   ↓  档案召回：取出最近 N 条记录作为上下文
   ↓  DeepSeek API（军师 SKILL.md + 按需检索的参考知识 + 对话记录）
   ↓  输出校验：拦截"说给用户听的话"，不合格重写或放弃
   ↓  模拟真人节奏，发回微信
```

---

## ⚠️ 先读这一节

### 1. 这会让你的微信号被平台处置

本项目通过 Windows UI Automation **操作你本机已登录的微信客户端**——
模拟点击、切换会话、读取界面消息、发送消息。这属于第三方自动化工具操作微信，
**不是你本人手动操作**。

微信的用户协议可能不允许这类自动化。实际风险包括功能限制、账号限制甚至封禁。
wxauto 官方文档自己也明确提示了这一点。

**强烈建议用微信小号跑，不要用主号。** 本项目不对任何账号后果负责。

### 2. 你的聊天内容会离开这台电脑

回复由 **DeepSeek API** 生成，这意味着：

- 每次要回复时，被召回的对话记录会作为提示词**发送给 DeepSeek 服务器**
- 召回条数由 `对话记录.召回条数` 控制（默认 30 条）
- 如果不想让某些内容外发，用白名单限制好友范围

对话档案本身只存在本机（`data/archive/`），本项目不上传任何数据到自己的服务器
（也没有这样的服务器），但**发往 DeepSeek 的部分不受本项目控制**。

### 3. 自动回复代表你本人说话

机器人会用你的账号、以你的身份对好友说话。建议先用一个测试好友观察几天，
确认语气和判断符合你的预期，再扩大名单。

## 功能

- **只回指定好友**：名单外的人和所有群聊一律不处理
- **本地对话档案**：机器人运行时把读到的消息存到本机，回复时带上上下文
- **多号共用一份记录**：同一个人的大号+小号可以共享同一份对话档案
- **连发合并**：对方连发多条时合成一批一起回应，不刷屏
- **像真人不像客服**：强制 JSON 输出 + 三道校验，拦截"建议你……""发个轻的"这类
  顾问口吻（这类话发出去一眼就暴露是机器人）
- **安全阀**：发送前校验目标会话、限流、无信息量消息不回复、危机信号转向关怀

## 环境要求

| 项目 | 要求 |
| --- | --- |
| 操作系统 | **Windows 10/11**（wxauto4 只支持 Windows） |
| Python | **3.9 – 3.12**（wxauto4 免费版限制，3.13 不行） |
| 微信桌面版 | **4.1.8.107**（wxauto4 免费版支持的上限） |
| DeepSeek | API 密钥，按官方价格计费 |

### 为什么必须把微信降到 4.1.8.107

微信 4.1.13 的 Qt 主窗口对 Windows UI Automation **完全不暴露控件树**。
实测：UIA 子树 **0 个节点**，MSAA 往下遍历一层直接访问违例崩掉进程。
而 wxauto4 是按 4.1.8 的控件结构（`ummui::MainWindow` 等）查找窗口的，
在新版上会报 `未找到已登录的客户端主窗口`。

历史版本安装包可以在 GitHub 上的版本归档仓库找到（例如
`SiverKing/wechat4.0-windows-versions`）。

**降级后请在微信设置里关闭自动更新**，否则会被顶回新版，方案立刻失效。

### 微信主窗口必须保持显示

微信 4.x 只在主窗口**可见**时才发布 UIA 控件树。最小化或收进托盘后，
wxauto4 会找不到主窗口。

`bot.py` 启动时会自动尝试把主窗口调出来，但**运行期间请不要最小化微信**。

## 安装

```powershell
# 1. 建一个 Python 3.9-3.12 的环境（conda 或 venv 都行）
conda create -n wxjunshi python=3.11 -y
conda activate wxjunshi

# 2. 安装依赖
pip install -r requirements.txt

# 3. 获取军师 skill（不打包在本仓库里，需要单独克隆）
git clone https://github.com/shengjidaguai-china/goutoujunshi.git

# 4. 配置
copy config.example.json config.json
#    然后编辑 config.json：打开开关、填好友备注名

# 5. 设置 DeepSeek 密钥
setx DEEPSEEK_API_KEY "sk-你的密钥"
#    重新打开终端让环境变量生效

# 6. 自检（不碰微信，只检查配置/技能/密钥/API/微信连接）
python bot.py --check

# 7. 启动
python bot.py
```

`bot.py` 会自动在几个常见位置查找 skill；找不到就设环境变量：

```powershell
setx GOUTOUJUNSHI_SKILL_DIR "D:\path\to\goutoujunshi"
```

也可以直接双击 `1-自检.bat` / `2-启动.bat` / `3-试跑一条消息.bat`。

## 配置

编辑 `config.json`（该文件已被 `.gitignore` 忽略，不会进版本库）。

### 好友列表与对话档案

```json
"好友列表": {
  "列表": [
    { "名字": "张三",     "档案": "张三", "备注": "大号" },
    { "名字": "张三小号", "档案": "张三", "备注": "小号和上面共用记录" }
  ]
}
```

- `名字`：微信里显示的**备注名**，必须完全一致
- `档案`：不写就用自己的名字（= 独立记录）；写同样的值 → **共用一份对话记录**
- 共用时机器人知道这是同一个人，会在提示里说明"对方用另一个号也在跟你聊"

### 主要配置项

| 配置 | 说明 |
| --- | --- |
| `启用开关.自动回复` | 总开关，默认 `false` |
| `好友列表.列表` | 要自动回复的好友，空 = 谁都不回 |
| `对话记录.启用归档` | 是否把读到的消息存到本地 |
| `对话记录.归档全部读到的消息` | `true`=读到的都存；`false`=只存回复过的 |
| `对话记录.召回条数` | 每次回复带多少条上下文（默认 30） |
| `对话记录.保留天数` | `0`=永久；设 30 则只留最近 30 天 |
| `对话记录.合并连发消息` | 连发合成一批一起回 |
| `AI.模型` | 默认 `deepseek-chat`（`deepseek-flash` 是推理模型，内容会跑进 reasoning 字段） |
| `回复行为.回复前延迟秒数范围` | 收到消息后等几秒再回，模拟真人 |
| `回复行为.同一好友最短回复间隔秒` | 防刷屏 |
| `轮询.轮询间隔秒` | 默认 5 秒 |
| `安全.忽略自己发的消息` | 默认 `true` |

## 对话档案：为什么是"边跑边存"

**微信不开放聊天记录，也回读不了历史消息。** 这是实测确认的，三条路都堵死：

| 尝试 | 结果 |
| --- | --- |
| `wxauto4.LoadMoreCache()` | ✗ 坏方法：`WeChatMainWnd` 缺 `load_more_message` |
| UIA `ScrollPattern` 滚动消息区 | ✗ 所有元素取到的都是空指针，无法滚动 |
| 直接读微信本地数据库 | ✗ 数据库加密；且属于破解，本项目不做 |

所以唯一可行的办法是**运行时边读边存**：机器人每次轮询读到会话内容，
就把看到的每一条写进本地档案。**跑得越久档案越完整**；机器人没运行期间
收发的消息，如果在你下次打开该会话时仍在可见区域内，也会被补录。

档案是纯文本 JSONL，每行一条，可以直接打开看：

```
data/archive/Jeremy.jsonl
```

```json
{"t":"msg","ts":1790165423.6,"person":"Jeremy","sender":"friend","type":"text","content":"我好累啊","fp":"...","replied":true}
```

字段：`person` 是哪个号发的，`sender` 是 `self`/`friend`/`system`，
`replied` 标记这条是否触发过回复。

**隐私提醒**：档案里有你的完整聊天记录，已被 `.gitignore` 忽略。
分享项目或截图时注意别把它带出去。

## 怎么保证发出去的像真人

军师 skill 原本是"顾问对人说话"，会输出"建议你……""单看这一件事……"这类
**给用户看的策略分析**。实测确实漏出来过：

```
对方：她三天没回我消息了，我该怎么回
模型：发个轻的就行，别追问：最近忙啥呢？     ← 这是策略，不是消息，发出去就露馅
```

所以加了三道闸：

**一、强制结构化输出。** 模型只能返回 JSON：

```json
{"messages": ["在忙吗？"], "skip": false}
```

`messages` 里每一项就是对方手机上会收到的一行字。

**二、输出校验 + 自动重试。** 检查每条消息，命中就判定不合格：
含"发个""别追问""等她回""先别""观察""看反应""建议你""第一步"等说给用户听的词、
以冒号结尾、含"单看""这说明"等分析口吻。不合格带纠正提示重写，最多 3 次；
仍不合格**本条不回复**——宁可不回，也不发莫名其妙的话。

**三、无信息量消息确定性拦截。** 靠模型判断"嗯""哦""哈哈"该不该回不稳定
（实测同一条"嗯"有时回有时不回），所以 12 字以内的纯语气词/纯符号直接不回复，
连 API 都不调。

回复风格上，人设要求**条数按需要定、不设上限**，以把对方说的每件事都回应到为准，
并且要有来有回、主动推进话题：

```
对方连发「在吗」「我很难受」「他把我删了」
军师：在 / 怎么了，出什么事了 / 你先别急，慢慢说
```

## 排错

| 现象 | 处理 |
| --- | --- |
| `未找到已登录的客户端主窗口` | 微信版本高于 4.1.8.107，或主窗口被最小化/关闭 |
| 日志里 `AttributeError: GetNewMessage` | 用了 wxauto4 的 `AddListenChat`；本项目已改用轮询 |
| 回复不出现 | 确认 `启用开关.自动回复` 是 true；看 `logs/bot.log` |
| 回复内容是空的 | 模型换成推理模型了，`AI.模型` 改回 `deepseek-chat` |
| 好友没反应 | 名字和微信显示的备注名不一致；启动日志会打印每份档案的成员 |
| 中文输出乱码 | 用 `--check` 或 bat 启动（脚本会强制 UTF-8） |
| `.bat` 报"不是内部或外部命令" | Python 不在 PATH；或脚本被用 UTF-8 编码保存过（本项目用纯 ASCII + CRLF） |

## 边界与安全设计

军师 skill 自身的安全边界会被遵守：

- 不诊断心理疾病，不用标签替代行为证据
- 不保证话术能让特定的人喜欢上你
- 不协助操控、PUA、贬低、服从测试、煤气灯、跟踪、性胁迫
- 出现家暴、跟踪、胁迫、人身威胁、自伤风险时，转向确认安全并建议联系可信支持

工程上的安全设计：

- **发送前校验目标会话**（`ChatInfo` 名称必须匹配），实测 `ChatWith` 有约 1/5 概率
  切换失败，没有这道校验会**把消息发给错误的人**
- **切换后校验**，不一致就跳过
- **限流**：同一好友最短回复间隔、回复前随机延迟
- **首次见到的会话只建立基线**，不回复历史消息
